## Description
The current test suite checks many compiler stages, but it does not systematically execute `spec/examples/valid/*.lane` through the user-facing `lane run --entry` path. Manual smoke testing found multiple runtime and Buslane lowering bugs that normal checks did not catch.

Observed successful entries include:

```sh
moon run lane-tools/lane -- run spec/examples/valid/01_top_level_forward_function_value.lane --entry answer --stdlib lane-std
moon run lane-tools/lane -- run spec/examples/valid/05_top_level_contextual_offer.lane --entry chosen --stdlib lane-std
moon run lane-tools/lane -- run spec/examples/valid/10_nominal_types.lane --entry user_id --stdlib lane-std
```

Observed failures are tracked in ISS-004, ISS-005, ISS-006, and ISS-008.

## Design
Add an automated smoke test or script that runs selected top-level value entries from `spec/examples/valid` through `lane run --entry`. The test should use the repository's `lane-std` explicitly and should guard against hangs with a timeout where the test environment supports it.

The test should not treat files without top-level values as failures. Function entries may be checked separately by expecting `<function>`.

## Acceptance Criteria
- [ ] The repository has an automated smoke check for selected `spec/examples/valid` entries through `lane run --entry`.
- [ ] The smoke check includes at least integer value output, nominal data output, and function entry output.
- [ ] Integer value output is asserted in source-style form such as `1 : Int`, not internal runtime form such as `int 1`.
- [ ] The smoke check covers at least one struct/enum match example after ISS-004 is fixed.
- [ ] The smoke check covers the builtin value case after ISS-006 is fixed.
- [ ] The smoke check has a finite timeout or equivalent protection against renderer/runtime hangs.
