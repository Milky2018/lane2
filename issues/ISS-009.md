# ISS-009: Add ABI signatures to native function externals

## Description
Buslane external declarations are values. A function external is a value whose Buslane type is a function type, and the runtime should resolve it to a native function value rather than invoking the external symbol directly.

After moving toward a value-resolver architecture, native functions still need an explicit ABI-level signature. The Buslane type, such as `(Int, Int) -> Int`, describes the language-level type. A native ABI signature describes the runtime calling convention and representation, such as a MoonBit-native function from two `Int64` values to one `Int64` value.

Without this metadata, a runtime resolver can return a native function whose implementation does not match the declared Buslane type. That mismatch would only surface as a runtime failure, or worse, as undefined behavior at the host boundary.

## Design
Introduce an ABI signature model for native function runtime values and standard intrinsic declarations. The design should distinguish at least:

- the declared Buslane type attached to the external value;
- the ABI signature used by the native runtime function;
- the conversion or compatibility rule between the ABI signature and the Buslane type.

The check should happen in an external linking/checking phase or resolver phase, not in ordinary source type checking. The source type checker should continue treating `builtin("...")` as unsafe and opaque except for its adjacent expected type. Standard intrinsics may be checked by `lanec` because their declarations are part of the standard runtime contract.

The resolver contract should be able to reject mismatches with a structured diagnostic. For example, resolving `%i64_add` against a declared Buslane type other than `(Int, Int) -> Int` should fail before evaluation.

## Acceptance Criteria
- [ ] Native function runtime values carry an ABI signature or equivalent runtime-call metadata.
- [ ] Standard intrinsics declare both their Buslane type contract and native ABI signature.
- [ ] External resolution checks that a resolved native function is compatible with the declared Buslane type.
- [ ] A mismatch such as resolving `%i64_add` at a non-integer function type reports a structured linker/runtime diagnostic before invocation.
- [ ] The source type checker does not directly inspect arbitrary builtin strings.
- [ ] Tests cover a valid standard intrinsic resolution and an ABI/type mismatch.
