# ISS-001: Resolve top-level function bodies with complete top-level values

## Description
`spec/examples/valid/01_top_level_forward_function_value.lane` is valid under the language specification, but the current implementation rejects it with `unresolved_value answer`.

The specification says top-level value definitions are ordered for their own initializers, while top-level function bodies are resolved after the complete top-level function, value, and contextual offer environments are known. Therefore a top-level function body may refer to a top-level value declared later in the file.

## Design
Adjust name resolution so top-level declarations are handled in phases: collect top-level type, function, value, and contextual offer bindings as required by the specification, resolve ordered top-level value initializers with only earlier values/offers, and resolve top-level function bodies with the complete top-level environment.

Do not make top-level value initializers forward-visible to later values; `spec/examples/invalid/02_top_level_let_forward_value.lane` must remain rejected.
