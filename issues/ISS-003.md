## Description
`spec/examples/valid/11_function_types.lane` is valid under the language specification, but the current implementation rejects the annotated generic binding:

```lane
let id_poly : [A](A) -> A = fn[A](value) {
  value
}
```

The diagnostic is `cannot_infer function literal parameter`, followed by a mismatch against the expected `forall` function type. The specification permits generic function literals to use an immediately surrounding generic function type as direct context.

## Design
Extend direct-context checking for function literals to generic function literals. When the expected type is `forall A. (T1, ..., Tn) -> R`, checking `fn[A](x1, ..., xn) { body }` should bind corresponding type parameters, use the expected parameter types for omitted parameter annotations, and check the body against the expected result type.

Do not perform non-local inference or infer missing type parameters from later calls. This is direct context inference only.
