# ISS-008: Render lane run values with source-style type annotations

## Description
`lane run --entry` currently renders primitive runtime values using internal runtime tags such as:

```text
int 1
```

The user-facing debug output should be source-style and include the selected entry type:

```text
1 : Int
```

The current format exposes implementation representation instead of the language-level value. This matters for the command-line tool because `lane run` is the first user-facing execution path.

## Design
Introduce a `lane run` debug renderer that combines the selected `BuslaneEntry` type with the runtime value. `BuslaneEntry` already stores `type_`, so the renderer should not rely on `BuslaneRuntimeValue` alone when producing command output.

For primitives, render source-style values followed by ` : Type`. Function entries may continue to render as an opaque callable such as `<function> : (T1, ..., Tn) -> R` if the type is available. Nominal data rendering should also move toward source-style output, but the first required fix is primitive values.

This issue is about user-facing output, not evaluation semantics.

## Acceptance Criteria
- [ ] `lane run` renders an integer entry as `1 : Int`, not `int 1`.
- [ ] Boolean, string, and unit entries render with source-style values and type annotations.
- [ ] Function entries include their function type or otherwise use a documented finite callable rendering.
- [ ] The implementation uses the selected entry's Buslane type when rendering the output.
- [ ] Regression tests cover at least an integer entry through `lane run` or the command-layer rendering helper.
