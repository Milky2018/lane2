# ISS-006: Distinguish builtin values from callable external functions at runtime

- Type: bug
- Status: closed

## Description
`spec/examples/valid/07_builtin_expected_type.lane` contains:

```lane
let host_value : Int = builtin("%host_value")
```

Running it as an entry currently prints `<function>`:

```sh
moon run lane-tools/lane -- run spec/examples/valid/07_builtin_expected_type.lane --entry host_value --stdlib lane-std
```

This is wrong for a value checked as `Int`. The runtime currently installs every Buslane `External(id)` as a callable external reference, and `BuslaneRuntimeValue::is_function` treats `External(_)` as callable. That conflates an unsafe builtin expression with a zero-argument external function or external value.

## Design
Define runtime semantics for `builtin("...")` according to its checked type. A builtin used at non-function type should not be presented as a callable function. Possible approaches include invoking zero-argument external values during evaluation, adding distinct runtime representations for external values and external functions, or requiring the external runtime handler to produce the value when the external is evaluated.

The design must keep standard intrinsic calls such as `builtin("%i64_add")(a, b)` working.

## Acceptance Criteria
- [x] `lane run spec/examples/valid/07_builtin_expected_type.lane --entry host_value --stdlib lane-std` no longer prints `<function>` for a value typed as `Int`.
- [x] Standard callable intrinsics used by the prelude still work for integer arithmetic and comparisons.
- [x] Runtime tests cover a builtin used as a value and a builtin used as a callable function.
- [x] Unsupported host builtins report a finite external diagnostic instead of being silently displayed as functions.
