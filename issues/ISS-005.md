# ISS-005: Prevent runtime pretty printing from recursively expanding closure environments

## Description
Selecting certain top-level entries with `lane run --entry` can hang while printing the runtime value.

Observed command:

```sh
/opt/homebrew/bin/timeout 8s moon run lane-tools/lane -- run spec/examples/valid/08_struct_forwarding.lane --entry meter_equal_ops --stdlib lane-std
```

This timed out. The file checks successfully, so the failure appears during runtime evaluation or debug rendering. The likely cause is `buslane/interpreter/pretty.mbt` printing closures by recursively printing their captured runtime environment. A top-level value such as `meter_equal_ops` contains functions/closures, and those closures may capture an environment containing the same or related top-level values, leading to unbounded output expansion.

## Design
Change runtime value pretty printing so closures and type closures render as opaque callable values, or render only stable metadata such as parameter IDs without expanding captured environments. `lane run` debug output should be finite and useful for arbitrary runtime values.

This is a display/runtime tooling fix. It should not change evaluation semantics.

## Acceptance Criteria
- [ ] `lane run spec/examples/valid/08_struct_forwarding.lane --entry meter_equal_ops --stdlib lane-std` returns or reports a finite diagnostic instead of hanging.
- [ ] Runtime pretty output for `Closure` and `TypeClosure` does not recursively print captured environments.
- [ ] A regression test covers pretty rendering of a value containing a closure whose environment refers to top-level values.
- [ ] Existing `lane run` behavior for plain integers and nominal data remains readable.
